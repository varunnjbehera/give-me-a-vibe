# Give Me a Vibe

> Give me something to build.

An extremely simple internet toy: pick a vibe, press one giant button, and receive a detailed product concept generated by Gemini — complete with a critical verdict.

No text inputs. No accounts. No database. No saved history. No idea repository. Each idea is generated fresh and is ephemeral.

## Vibe modes

- **Useful** — practical concepts with rigorous, restrained evaluation.
- **Weird** — stranger, niche, unconventional but buildable concepts.
- **Absurd** — ridiculous premises that remain technically imaginable, judged deadpan.
- **Satirical** — parody concepts (fake startups, corporate/VC/productivity culture), delivered straight.

The mode materially changes generation, tone, and verdict — it is not a visual filter.

Ideas are generated dynamically by Gemini. There is no hardcoded idea list, seed library, or rotation to fake randomness.

The model is intentionally anti-sycophantic: novel does not mean good, useful does not mean commercially viable, and a bad business can still be a good build. Verdicts are specific and can be reluctantly positive, but never use hollow praise and never fabricate market stats.

## Tech stack

Next.js + TypeScript + React + Tailwind CSS. Zod for validation. `html-to-image` (lazy-loaded, client-side only) for image export. No auth, DB, or storage libraries.

## Local development

```bash
npm install
cp .env.example .env   # then fill in GEMINI_API_KEY
npm run dev            # http://localhost:3000
```

## Environment variables

| Name | Scope | Value |
| ---- | ----- | ----- |
| `GEMINI_API_KEY` | Server-side only. Never prefix with `NEXT_PUBLIC_`. | From https://aistudio.google.com/apikey |
| `GEMINI_MODEL` | Server-side only. | e.g. `gemini-3.5-flash-lite` |

`.env` is gitignored — never commit keys. `.env.example` contains names only.

## Running locally

`npm run dev` serves the landing state (`IDLE → GENERATING → RESULT | ERROR`). Generation calls `POST /api/vibe`; the optional builder panel calls `POST /api/build-prompt`. Both require `GEMINI_API_KEY` at runtime, not at build time.

## Build / lint

```bash
npm run lint
npm run build
npm test
```

`npm test` runs `vitest run` (schema + share-detail unit tests).

## Vercel deployment

1. Push this repo to GitHub (`.env` stays local).
2. Import in Vercel → Framework: Next.js (defaults work, no `vercel.json` needed).
3. Add Environment Variables `GEMINI_API_KEY` + `GEMINI_MODEL` (Production + Preview; Development if you use `vercel dev`).
4. Deploy. No build config, no DB, no extra services.

`maxDuration = 30` on the API routes exceeds the Vercel Hobby plan's limit (Hobby clamps it rather than failing the build; Pro honors 30s). Each handler aborts upstream at 25s, so behavior is graceful either way.

## Project architecture

```text
Landing UI
   ↓
Vibe selection
   ↓
/api/vibe
   ↓
Gemini
   ↓
validated structured result
   ↓
dynamic result renderer
```

Generation flow:

```text
Client (page.tsx state machine)
  POST /api/vibe { vibe: useful|weird|absurd|satirical, recentTitles?: string[0..3] }
    → lib/prompt.ts builds system instruction (MODE: <VIBE>)
    → per-request seed + rotating variation lens + temperature jitter (1.0–1.2)
    → fetch generativelanguage.googleapis.com (server-side only)
    → responseMimeType: application/json + responseSchema
    → lib/schema.ts Zod-validates, sanitizes (Unicode-safe)
  ← { vibe, idea: { title, premise, sections[], verdict, metadata?, tags? } }
```

The generating vibe is frozen into the result at creation time
(`{ name: "result", idea, vibe }`). Switching the selector afterwards only
affects the *next* generation — labels, Markdown, share text, and the image
card all use the pinned vibe, never the live selector.

### Prompt architecture (`lib/prompt.ts`)

- Persona: skeptical creative director, not a cheerful ideation assistant.
- `MODE` materially changes generation + tone + verdict (not a visual filter).
- Anti-sycophancy: novel ≠ good, useful ≠ viable, weird ≠ clever, satire ≠ automatically funny. Bans hollow praise.
- Specificity: concrete user, behavior, mechanics, differentiator. Bans generic AI-assistant / dashboard / habit-tracker defaults.
- Verdict required: specific criticism, reluctantly positive when earned (`Annoyingly, this is good`), never fabricates market stats.
- Safety: prompt-engineered guardrails; unsafe directions redirect to harmless absurd/satirical equivalents.
- Variety without an idea list: each request carries a unique seed + one rotating abstract variation lens + slight temperature jitter, plus the client's last ≤3 titles as a short-lived session avoid-hint. No hardcoded idea repository, topic list, or templates.

### UI state machine (`app/page.tsx`)

`IDLE → GENERATING → RESULT | ERROR`, one tap back to `GENERATING`.

- Landing: giant `SURPRISE ME` CTA + 4-way `VibeSelector` radio-group.
- Result: editorial artifact (`IdeaView` + `Verdict`) + optional `Get the build prompt` builder panel + `Copy Markdown` / `Share` (Web Share API + clipboard fallback) / `Save image` (client-side `html-to-image` of a curated card: title + premise + 1–2 details from dynamic sections + verdict + pinned vibe, with dynamic title sizing) + dominant `Give me another vibe` regeneration. On success the page scrolls to the result and focuses the idea title (instant scroll under `prefers-reduced-motion`).
- Errors: deadpan `The vibe escaped.` + retry (throttled requests get `The muse needs a breather.` with the server's `Retry-After` hint). Image-export failures show `The image refused to cooperate.` + retry without losing the result. No raw API errors in UI.

### Second call — build prompt (`app/api/build-prompt/route.ts`)

Opt-in second LLM call, documented separately because it is not part of the core generation loop:

```text
Client (result state)
  POST /api/build-prompt { idea, vibe, target? }
    → revalidates idea against IdeaSchema (never trusts client shapes)
    → lib/buildPrompt.ts builds builder instruction (TARGET: <AGENT>)
    → fetch generativelanguage.googleapis.com (server-side only, temp 0.7)
    → responseMimeType: application/json + builder responseSchema
    → lib/buildSchema.ts Zod-validates, sanitizes
  ← { vibe, target, buildPrompt: { title, target, prompt, sections? } }
```

Only fires on explicit `Get the build prompt` (target picker: Generic / Open Code / Claude Code / Codex / Cursor, default Generic). The response carries the source identity so a stale reply can never attach to a newer result. Regenerating the idea clears the old build prompt.

### Rate limiting (`lib/rateLimit.ts`, shared)

`POST /api/vibe` and `POST /api/build-prompt` share best-effort per-IP
throttling: 10 requests / 60s sliding window, `429 + Retry-After` when
exceeded, surfaced through the existing deadpan error states.

Tradeoff, stated plainly: this is an **in-memory bucket per serverless
instance**, not globally enforced distributed rate limiting. It stops casual abuse and accidental loops but is **not** a quota guarantee. Global enforcement would need a shared store (e.g. Upstash Redis); that was deliberately not added to preserve the ephemeral, zero-infrastructure architecture.

## Notes

- Model text is rendered as text (never `dangerouslySetInnerHTML`).
- Sanitization strips `U+FFFD` replacement chars + control chars only; emoji, accents, and non-Latin scripts are preserved.
- Respects `prefers-reduced-motion`, keyboard nav (incl. arrow keys on the vibe group), focus states, single live region.
- Keep it restrained: better execution of the core interaction beats more features.
